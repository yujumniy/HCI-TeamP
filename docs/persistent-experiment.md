# v1 영구 저장 통합 화면

브랜치 `feature/persistent-experiment`는 점검본 `feature/readiness-check` 위에 4번의 화면 연결을 추가합니다.

## 실행

폰 기본 앱 → **실험 준비** → **참가자 새로 등록** 또는 기존 참가자 **계속하기**를 선택합니다. 참가자 번호와 조건·과제 순서는 Room에 저장합니다. 완료·TIMEOUT 과제는 건너뛰고, INVALID 과제는 새 시도 번호로 재개합니다.

워치에는 같은 서명으로 만든 wear APK를 설치하고 앱 목록의 **워치 실험 진행**을 엽니다. 폰에서 워치 조건에 도달하면 **워치에 시행 전달**을 누릅니다. 워치의 **준비**로 시행을 시작하고, 결과가 저장·전송된 뒤 폰의 **결과 저장 확인**으로 다음 과제를 진행합니다. 연습 피드백은 시행 기기에 표시합니다.

C1·C2·C3·C4 전체 조건 순서를 유지합니다. 각 조건의 연습 2회와 본 시행 8회를 포함한 총 40회입니다. 폰 시행과 워치 시행 모두 동일한 RecordedTrial 제어를 사용하며, 실제 측정은 해당 기기의 단조 시계에서 이루어집니다.

## 관리자 기능

- 참가자 순차 등록과 저장된 배정 순서 조회
- 앱 재시작 시 중단 시도 INVALID 복구 및 다음 시도 번호 발급
- 관리자 긴급 중단과 INVALID 재시도
- T3 통신 검증 화면 진입
- 참가자별·전체 CSV ZIP 수동 내보내기
- 전 조건 종료 시 무결성 검사와 참가자 자동 백업
- 파일 생성 성공과 검증 통과를 별도로 표시

실제 시행 화면에는 남은 시간이나 정답 피드백을 표시하지 않습니다. 준비·카운트다운 중에는 시작값·목표값이 숨겨집니다. 목표값과 달라도 완료할 수 있습니다. 폰 시스템 미디어 음량이 0이면 시행 전 설정을 안내하며, 앱이 시스템 음량을 자동 변경하지 않습니다.

## 검증 범위와 남은 의존성

이 통합본은 기술 검증용입니다. 폰·워치의 실제 송수신·저장·재연결·백업은 실제 기기에서 확인해야 합니다. 새 기능 단위 테스트는 저장 완료 전 진행 차단, 원시 누름/해제, 실제 값 변경, timeout 경계와 40개 과제 구성을 확인합니다.

팀원 3의 feat/data-sync-fix 수정본을 통합했습니다.

- 진행 중 기록은 NOT_READY로 두고 종료된 PENDING 기록만 전송합니다.
- 해시 불일치와 진행 중 수신은 정상 시행 데이터에서 거부하고 receive_errors에 보존합니다.
- 관찰된 입력 이벤트를 순서대로 저장 큐에 넣어 시행 중에도 DB에 기록하며, 재실행 시 저장된 이벤트를 유지한 INVALID 복구를 수행합니다.
- DB v1→v2 마이그레이션이 포함되어 있습니다. 원본 보존과 실제 강제 종료 복구는 실기기에서 확인해야 합니다.

원시 입력 DOWN/UP은 기록기에 연결하며, 경계·차단·회전 등 추가 원본은 sync_log에 저장합니다. 추정 베젤 접촉을 INPUT_DOWN으로 만들어 기록하지 않습니다.
UI 버튼 확대·중앙 배치·목표 눈금과 오디오 곡선 변경은 팀 논의 후 별도로 적용합니다. 이전 리허설 코드는 남아 있으며, 기본 앱의 실험 준비 진입점은 영구 저장 통합 화면을 사용합니다.
