# 명세서 v1 · 실험 진행 구현

공통 코드에서 조건 순서, PR01·PR02, T01~T08의 값과 배정 순서, 시도 ID 형식을 정의합니다. 참가자 번호에서 순서를 재현할 수 있습니다. 3초 카운트다운 뒤 시작값과 목표값을 공개하고, 30초 제한을 화면에 표시하지 않습니다. 참가자가 완료를 누르면 음량이 목표값과 달라도 COMPLETED로 기록합니다. 조건 간 휴식은 최소 30초입니다.

`TrialRecord.eventLog()`는 START, 실제로 관찰된 VALUE_CHANGE, 종료 이벤트에 시도 ID와 순서 번호를 부여합니다. `calculateMetrics()`는 같은 기록에서 최대 오버슈팅, 초과 진입 수, 최종 오차, 목표 최초 도달, 방향 전환, 이동 거리, 첫 값 변경을 계산합니다. 원시 INPUT_DOWN/UP과 동기화 이벤트 수집, 원본 영구 저장, CSV·ZIP은 담당 구현과 연결해야 합니다.

폰의 **실험 준비**에서 두 폰 조건의 진행을 리허설합니다. 가상 음량을 버튼으로 조절하고, 시도 결과는 세션 메모리에만 둡니다. 실제 C1·C2 입력, 워치 핸드오프, 참가자 순번의 영구 할당이 연결된 뒤 실험용 경로를 활성화할 수 있습니다.

공통 리소스의 `experiment_ringtone.wav`는 합성한 2음의 임시 벨소리입니다. 폰은 사전 로딩한 벨소리를 시행 중 반복 재생하며 플레이어의 선형 게인만 바꿉니다. 같은 리소스를 워치에서도 사용할 수 있으며, 최종 음원·스피커 출력·양 기기의 시스템 음량 유지 여부는 실제 기기에서 확인합니다.
